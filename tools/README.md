# Tools

Status: **Active** (last updated: 2026-08-23)

The tools directory contains the generators, qualification gates, adapters, and measurement wrappers used by the repository. The reference `Makefile` is the maintained command entry point for corpus generation and qualification. The Zig build steps are the maintained entry point for installing the Zig adapters.

## Commands

Validation:

- `make -C ref check-byte-fixtures` checks generated byte-sensitive fixtures.
- `make -C ref check-corpus` checks the fixture manifest against applicable parser lanes.

Local benchmark definitions:

- `make -C ref check-shape-matrix` checks the ignored workload and oracle plans under `bench/` against the fixture manifest.
- `make -C ref check-persistent` checks the persistent adapter protocol against the ignored smoke input under `bench/`.

Generated data:

- `make -C ref generate-corpus check-generated` generates and qualifies the common-summary and malformed-input corpus.
- `make -C ref generate-namespace-corpus verify-namespace-corpus` generates and verifies namespace-churn data.
- `make -C ref check-generated-persistent` checks resident and streaming output from the maintained persistent adapters.

Standards data:

- `make -C ref check-unicode-table` checks the committed XML 1.1 normalization table.
- `make -C ref fetch-xmlconf check-xmlconf` obtains the pinned W3C suite and runs its processor-aware classifier.

Measurement:

- `run-zebrac-aa.py` measures one command through two names to expose host noise.
- `run-zebrac-matrix.py` measures only correctness-qualified target and workload pairs.
- `run-valgrind.py` runs Memcheck only on explicitly selected correctness-passing pairs.

`bench/` and `data/` are ignored. The former contains local plans and small benchmark inputs; the latter contains generated inputs, downloaded corpora, and results. Benchmark generators write under `data/`. Correctness generators update their tracked fixture or source output and provide a check mode. No local benchmark result is a repository contract.

## Zig adapters

`z_xml_check.zig`, `z_xml_persistent.zig`, and `z_xml_tree.zig` provide the common-summary, persistent-protocol, and owned-tree command adapters. `z_xml_validation_repeat.zig` provides the fresh versus reused validation measurement adapter. Build them through the explicit steps:

```sh
zig build --build-file tools/build.zig corpus-adapters -Doptimize=ReleaseFast
zig build --build-file tools/build.zig persistent-adapters -Doptimize=ReleaseFast
zig build --build-file tools/build.zig tree-adapter -Doptimize=ReleaseFast
zig build --build-file tools/build.zig validation-bench -Doptimize=ReleaseFast
```

`zig build --build-file tools/build.zig tools -Doptimize=ReleaseFast` installs the union of the adapter steps, including the generalized-encoding persistent adapter currently classified under `experimental-adapters`. `zig build --build-file tools/build.zig test` runs only the tool-local tests.

## Declarations and boundaries

`tools/z-xml-targets.tsv` declares the focused z-xml corpus profiles. `ref/targets.tsv` declares the reference-laboratory profiles. `ref/persistent-targets.tsv` is the descriptive declaration for persistent peer targets and is intentionally separate from the parser-capability matrix.

The Zebrac wrappers resolve `zebrac` from `PATH` by default. An explicit `--zebrac` argument remains available for a deliberate override. Reference source and fallback toolchain acquisition remains owned by `ref/build.sh` and its documented cache; the wrappers do not create local command aliases.
