# Tools

Status: **Active** (last updated: 2026-08-22)

The tools directory contains the generators, qualification gates, adapters, and measurement wrappers used by the repository. The reference `Makefile` is the maintained command entry point for corpus generation and qualification. The Zig build steps are the maintained entry point for installing the Zig adapters.

## Maintained surfaces

| Surface | Entry point | Owns |
| --- | --- | --- |
| Checked-in fixture consistency | `make -C ref check-byte-fixtures check-shape-matrix` | Generated byte fixtures and shape/oracle manifest consistency |
| Common generated corpus | `make -C ref generate-corpus check-generated` | Versioned no-DTD corpus bytes, summaries, and rejection positions |
| Namespace generated corpus | `make -C ref generate-namespace-corpus verify-namespace-corpus` | Namespace-churn bytes and expanded-name summaries |
| Persistent qualification | `make -C ref check-generated-persistent` | Exact resident/streaming output for the maintained peer and z-xml adapters |
| Small persistent smoke gate | `make -C ref check-persistent` | Fixed-fixture protocol combinations before generated qualification |
| Unicode normalization table | `make -C ref check-unicode-table` | Reproducibility of the committed XML 1.1 property table |
| W3C XML catalog | `make -C ref fetch-xmlconf check-xmlconf` | Pinned suite acquisition and processor-aware classification |
| Zebrac A/A | `run-zebrac-aa.py` | Same-program host-noise comparison through two names |
| Zebrac matrix | `run-zebrac-matrix.py` | Eligibility-aware lane selection and saved measurement bundles |
| Memcheck | `run-valgrind.py` | Explicit correctness-passing parser pairs under Valgrind |

The generators write only derived data or an explicitly named generated source. The `--check` forms verify existing output without rewriting it. The namespace corpus has a separate manifest schema because its semantic summary is not the common event summary.

## Zig adapters

`z_xml_check.zig`, `z_xml_persistent.zig`, and `z_xml_tree.zig` provide the common-summary, persistent-protocol, and owned-tree command adapters. `z_xml_validation_repeat.zig` provides the fresh versus reused validation measurement adapter. Build them through the explicit steps:

```sh
zig build corpus-adapters -Doptimize=ReleaseFast
zig build persistent-adapters -Doptimize=ReleaseFast
zig build tree-adapter -Doptimize=ReleaseFast
zig build validation-bench -Doptimize=ReleaseFast
```

`zig build tools -Doptimize=ReleaseFast` installs the union of the maintained adapter steps. The generalized-encoding persistent adapter is kept under `zig build experimental-adapters` until it has a qualified generated lane.

## Declarations and boundaries

`tools/z-xml-targets.tsv` declares the focused z-xml corpus profiles. `ref/targets.tsv` declares the reference-laboratory profiles. `ref/persistent-targets.tsv` is the descriptive declaration for persistent peer targets and is intentionally separate from the parser-capability matrix.

The Zebrac wrappers resolve `zebrac` from `PATH` by default. An explicit `--zebrac` argument remains available for a deliberate override. Reference source and fallback toolchain acquisition remains owned by `ref/build.sh` and its documented cache; the wrappers do not create local command aliases.
