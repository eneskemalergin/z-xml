# XML Fixtures

Status: **Active** (last updated: 2026-08-22)

This tree is the small, checked-in correctness corpus. `manifest.tsv` is the machine-readable oracle. Every benchmark input must pass its declared correctness profile before zebrac may measure it.

- `valid/core/` contains well-formed XML 1.0 Fifth Edition documents that do not require namespace or DTD processing.
- `valid/encoding/` contains deterministic byte fixtures for BOMs, UTF-16 byte order, declared encodings, and line endings.
- `valid/namespaces/` contains documents valid under Namespaces in XML 1.0 Third Edition.
- `valid/dtd/` contains well-formed documents that satisfy their DTD validity constraints.
- `invalid/not_well_formed/` contains documents every conforming XML 1.0 processor for the declared feature set must reject.
- `invalid/encoding/` contains malformed UTF-8, UTF-16, XML character, and encoding-declaration byte sequences.
- `invalid/namespaces/` contains well-formed XML that violates Namespaces in XML constraints. Only namespace-aware processors are required to reject it.
- `invalid/dtd/` contains well-formed XML that violates DTD validity constraints. Validating processors reject it; non-validating processors normally accept it.
- `benchmark/` contains tiny benchmark smoke data and descriptions of generated or downloaded workloads. It never serves as a correctness oracle by itself.

After building the references with `make -C ref all`, run `make -C ref check-corpus` before any benchmark command.

`manifest.tsv` has schema marker `z-xml-fixtures-v1` and seven tab-separated fields: ID, relative path, classification, recommendation, required features or checks, benchmark eligibility, and description. Positive cases name accepted syntax features. Negative cases use `check_` capabilities so accepting valid syntax is not confused with detecting every malformed variant.

The byte fixtures are generated by `tools/generate-byte-fixtures.py` and checked byte for byte before the focused gate runs.

The checked-in focused z-xml baseline is 165 fixtures across ten target profiles: 857 asserted passes, 0 contradictions, 365 unsupported-feature combinations, 428 out-of-profile combinations, and 0 harness errors. The current peer reference matrix has 12 admitted contradictions, which remain visible in its result and never count as correctness success. Exclusions and contradictions are profile evidence, not correctness success.

`benchmark/plans/shape-matrix-v1.tsv` is the shape-level contract. It maps checked-in seed fixtures to scalable generators, parser profiles, input models, semantic oracles, and planned lanes. Validate its references with `python3 tools/check-shape-matrix.py`. Generated files remain outside Git.
